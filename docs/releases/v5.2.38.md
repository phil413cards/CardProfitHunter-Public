# CardProfitHunter V5.2.38

## Summary

V5.2.38 prevents stored opportunity and watchlist records from remaining
financially actionable after their supporting valuation expires or loses
verifiable provenance.

## Included

- Carries verified valuation status, verification date, expiry date, source
  URL, comp count, and safe notes into actionable analysis payloads
- Omits provenance content from rejected engine results while preserving
  explanatory safety flags
- Rechecks valuation provenance before storing financial opportunity and
  watchlist rows
- Downgrades missing, malformed, expired, unverified, demonstration, and
  non-actionable valuation payloads to PASS and clears financial fields
- Rechecks valuation freshness whenever dashboard KPIs, best opportunities,
  saved-search summaries, history, watchlist, or recent activity are read
- Treats legacy actionable payloads without complete provenance as
  non-actionable without rewriting or deleting stored rows
- Keeps valuations actionable through their stated expiry date and blocks them
  beginning the following UTC date
- Combines valuation and seller checks in the SQLite per-connection
  actionability boundary without a schema migration

## Safety Boundaries

This release does not modify existing database rows, increment the schema
version, add network calls, or change valuation matching and money formulas.
It does not change eBay request behavior, seller thresholds, CSV exports,
runtime configuration, or the local-only single-user operating boundary.
