# CardProfitHunter V5.2.28

## Summary

V5.2.28 makes missing and malformed listing text fail closed throughout the
card-analysis pipeline.

## Included

- Adds one shared scalar-text safety helper for `None`, `NaN`, `pd.NA`, blank
  strings, and malformed non-string values
- Prevents pandas missing values from raising ambiguous-boolean `TypeError`
  exceptions in card parsing, query parsing, relevance filtering, listing
  classification, grading estimation, Scout analysis, or direct financial
  analysis
- Labels absent required titles and conditions with stable `missing_title` or
  `missing_condition` reasons
- Labels malformed non-string required values with stable `invalid_title` or
  `invalid_condition` reasons
- Excludes incomplete rows before Scout ranking, including rows whose title is
  valid but whose required condition is absent
- Keeps rejected direct-analysis rows non-financial with no matched valuation,
  suggested offer, profit, ROI, or market-value fields
- Preserves existing classification, matching, and financial behavior for
  valid listing text

## Safety Boundaries

This release changes missing/malformed scalar-text handling only. It does not
change card identity rules for valid text, money formulas, eBay requests,
database behavior, CSV exports, dashboard filtering, stored user data, or
runtime configuration.
