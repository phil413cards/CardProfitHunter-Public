# CardProfitHunter V5.2.6

## Summary

V5.2.6 adds reproducible valuation-renewal checks and continuous integration
for the private, local-only controlled-demo baseline.

## Included

- Adds a read-only valuation renewal report with current, due-soon, expired,
  invalid, missing-provenance, and non-actionable classifications
- Adds a command-line renewal queue with deterministic as-of dates and review
  windows
- Documents the evidence-first valuation renewal workflow
- Adds GitHub Actions testing on Python 3.11 and 3.12
- Pins official checkout and Python setup actions to reviewed, Node 24-compatible
  commit SHAs
- Grants the workflow read-only repository-content permission and supplies no
  eBay credentials or GitHub secrets
- Adds a path-only guard that rejects tracked environment files, databases,
  token caches, virtual environments, generated output, logs, and test caches

## Safety Boundaries

The renewal audit reads and reports valuation metadata only. It does not call
eBay, edit the valuation CSV, write SQLite, or create output files. A row does
not become verified or actionable merely because it appears in the report.

The CI workflow does not receive eBay credentials. Existing tests continue to
mock HTTP activity and use temporary databases. The tracked-artifact guard
checks paths only and never reads file contents.
