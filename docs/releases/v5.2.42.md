# CardProfitHunter V5.2.42

## Summary

V5.2.42 makes verified-valuation freshness a release gate so stale financial
evidence cannot pass continuous integration unnoticed.

## Included

- Adds an opt-in `--fail-on-blocking` mode to the read-only valuation audit
- Makes CI reject expired verified valuations
- Retains fail-closed CSV validation for missing or malformed verified
  provenance
- Keeps due-soon valuations visible without failing CI
- Keeps demonstration and example-only rows non-actionable without treating
  them as CI failures
- Documents the CI gate and its local equivalent
- Adds CLI and workflow regression coverage

## Safety Boundaries

This release does not change valuation prices, expiry dates, card identity
matching, recommendation rules, money formulas, eBay requests, database
behavior, dashboard filtering, or application UI. The default valuation audit
remains informational; only the explicit CI mode returns an unsuccessful exit
status for blocking verified-valuation states.

- The bundled V5.2.41 valuation audit passed as of August 12, 2026 with six

- Tracked private runtime artifact guard passed
- `git diff --check` passed
- No live eBay call, credential access, real database write, valuation change,
