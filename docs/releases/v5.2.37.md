# CardProfitHunter V5.2.37

## Summary

V5.2.37 applies the approved seller-quality policy to persisted opportunity and
watchlist data so stored or legacy BUY/OFFER labels cannot bypass the engine.

## Included

- Centralizes seller eligibility evaluation for engine and persistence use
- Rechecks seller identity, rating count, and positive-feedback percentage
  before storing any financial opportunity or watchlist row
- Downgrades unsafe new writes to PASS and clears financial and valuation fields
- Rechecks stored payloads before dashboard KPI aggregation, best-opportunity
  selection, saved-search summaries, and top-opportunity display
- Sanitizes legacy history, watchlist, and recent-activity reads without
  rewriting the local database
- Treats missing, malformed, action-mismatched, and invalid JSON payloads as
  non-actionable
- Preserves total analyzed counts and valid historical rows whose stored seller
  data meets the approved thresholds
- Uses SQLite's per-connection deterministic eligibility function without a
  schema migration or dependency change

## Safety Boundaries

This release does not modify existing database rows, increment the schema
version, add automatic cleanup, or make network calls. Return-policy
verification remains manual. Money formulas, valuation matching, eBay request
behavior, CSV exports, runtime configuration, and stored user data are
unchanged.
