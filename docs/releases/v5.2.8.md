# CardProfitHunter V5.2.8

## Summary

V5.2.8 makes financial recommendations more conservative by incorporating
purchase tax, promoted-listing fees, expected return/defect loss, and grading
loss risk into one consistent total-modeled-cost framework.

## Included

- Adds required configurable assumptions for purchase tax,
  promoted-listing fees, return/defect allowance, and grading loss risk
- Applies those assumptions consistently to raw-flip and PSA expected profit,
  ROI, max-buy amounts, and suggested offers
- Fails closed when any required modeled cost is missing, nonfinite, negative,
  out of range, or when combined selling rates exceed the modeled sale value
- Adds conservative nonzero controlled-demo defaults and editable Streamlit
  controls for all four assumptions
- Documents the formulas, risk semantics, and known eBay fee approximation in
  `docs/PROFIT_MODEL.md`
- Adds regression coverage for exact cost arithmetic, recommendation
  thresholds, configuration validation, and app wiring

## Behavior Change

Previously marginal opportunities may now return `PASS` because tax,
promotion, expected return/defect loss, and grading loss risk reduce the safe
max-buy price. This is intentional. Users should replace the defaults with
rates supported by their location, eBay account, promotion strategy, return
history, and grading history before relying on results.

## Safety Boundaries

This release does not change card-identity matching, valuation provenance,
eBay API behavior, dashboard financial filtering, SQLite schema, or stored
user data. It does not make the application hosted or multi-user ready. No
automated purchase, offer, bid, or listing action was added.
