# CardProfitHunter V5.2.39

## Summary

V5.2.39 prevents an empty, failed, or partial Daily Buy Board run from leaving
an older successful batch visible as the current dashboard opportunity set.

## Included

- Records a sanitized outcome for every attempted Daily Buy Board run
- Tracks success, empty, partial, and failed statuses with aggregate counts
- Clears current financial KPIs and best-opportunity data after empty or failed
  runs while preserving historical opportunity records
- Limits partial-run dashboard results to that run's successfully processed
  listings
- Shows explicit empty, failed, and partial status messages on the dashboard
- Refreshes the dashboard after a completed board run without exposing stale
  prior results
- Adds an additive SQLite schema-v2 migration for batch outcomes
- Supports inspection and restoration of compatible schema-v1 backups, which
  are migrated before replacing the active database
- Includes recorded outcomes in explicit retention previews and cleanup while
  conservatively preserving the latest recorded run and latest snapshot batch

## Safety Boundaries

This release does not change card identity matching, valuation eligibility,
money formulas, seller thresholds, eBay requests, CSV exports, or the
local-only single-user operating boundary. The schema migration is additive
and does not rewrite existing opportunity, search, saved-search, or watchlist
rows.
